# 4. Architecture and Data-Flow Map

```text
host source/AST + filename/settings/options
  -> validated context + per-source/AST/config analysis cache
  -> lexical writes/references + path/authority/domain facts
  -> catalog gates and visitors -> diagnostics

catalog -> rule registry + presets + generated docs/configs
source -> local checks -> exact tarball + publish-input manifest
  -> isolated consumer execution -> OIDC publication
  -> registry/provenance reconciliation -> separate GitHub release

required validation -> acceptance capture -> explicit network consumer
                                              ^ OPS-004 boundary
```

Hosts own parsing and source identity. Settings are validated/frozen before sharing, while COR-019 shows crafted cache equivalence can reuse a formerly valid result. Public context runtime immutability is stronger than its signatures (API-004). Lexical indexes own binding/write facts; shared paths own environment/object/completion joins. Mutable callable facts still escape that state boundary (COR-003), and Fluent alias selection has independent source-order/unsupported-write defects (COR-006/COR-020).

Budgeted exhausted outcomes discard partial proof (POS-004). They do not currently account for aggregate alternative payload work (PER-007), independent retention subsets (PER-002), recursive Fluent resolution (REL-005) or preliminary scope scans (IMP-003). Fluent property proof must also respect spread precedence (COR-025). Offline engine/SDK facts retain separate version axes and explicit uncertainty.

Acceptance locks coordinate same-host local captures using complete-owner hard links, reread ownership and bounded waits; direct build/test calls are outside that lock. Registry release delivery is effectively once through immutable identity/reconciliation, with explicit absent/existing/ambiguous/permanent outcomes, not unconditional exactly-once delivery. REL-006 affects retry availability while provenance rejection remains fail-closed. Required acceptance capture additionally executes freshly installed foreign dependencies (OPS-004); separate consumer-job isolation does not remove that duplicated path.
