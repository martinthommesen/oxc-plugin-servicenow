# PR #51 acceptance ledger

This ledger contains one atomic row for each goal or omitted issue requirement. Historical implementation claims do not prove the current owning pull request head. The goal checkboxes can therefore record historical implementation work while this ledger keeps current verification `Pending`.

Readiness terms have these meanings:

- **Pending**: no current proof exists at the owning pull request head.
- **Verified-at-head**: focused proof passed at the exact recorded head.
- **Merge-ready**: all in-repository gates and governance checks passed at the current merge commit.
- **Live-pending**: only a protected post-merge tag, registry, or GitHub action can supply the proof.
- **Release-verified**: the stable protected-tag run supplied exact live evidence.

A row can become **Verified-at-head** only when it records a direct executable proof, a specific commit reachable from the owning pull request head, the exact command and environment used at that commit, and a current result linked to the same full head or merge commit. ## Required gates

The **merge gate** evaluates current code and configuration at the exact pull request head or merge commit. It requires applicable clean-checkout tests, real Oxlint and ESLint hosts, inspected-artifact checks, review, and executable governance checks. It does not require a stable tag.

The **release gate** starts only after merge on protected `main`. It requires a controlled protected tag, approved OpenID Connect (OIDC) publication, registry integrity and exact provenance identity, public imports, and the GitHub release.

## Layer rollback boundaries

1. Layer 1 can be reverted without retaining rules that depend on its context/settings contracts.
2. Layer 2 can be reverted together with dependent stateful consumers; later layers must not bypass it.
3. Layer 3 reverts classic/stateful consumers without reverting shared foundations.
4. Layer 4 reverts Fluent manifests and binding-aware rules without changing classic analysis.
5. Layer 5 reverts generated docs/evidence/profile/formatter changes with descriptors kept synchronized.
6. Layer 6 reverts packed compatibility/benchmark gates without changing release permissions.
7. Layer 7 is privileged and independently revertible; no implementation-layer changes belong in its commits.
