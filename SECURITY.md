# Security policy

## Supported versions

Security fixes target the latest published version.
Upgrade before you report a problem that might already be fixed.

## Report a vulnerability

Use [GitHub private vulnerability reporting](https://github.com/martinthommesen/oxc-plugin-servicenow/security/advisories/new).
Do not open a public issue for a suspected vulnerability.

Include these details when possible:

- Affected package version and runtime
- Impact and required attacker access
- Minimal reproduction steps
- Affected files or rules
- Suggested mitigation

Remove credentials, customer data, and proprietary ServiceNow code from every report and attachment.

The maintainer will acknowledge a complete report within seven days.
The maintainer will then confirm the impact and coordinate a fix.
The reporter and maintainer will agree on disclosure timing.
Do not disclose the issue before a fix or coordinated advisory is available.

## Scope

Security issues include:

- Code execution
- Release or provenance bypass
- Credential exposure
- Unbounded resource use
- Rule bypasses that weaken a documented security profile

Report ordinary false positives, false negatives, and feature requests in the public issue tracker.
Use private reporting when the defect creates a security boundary failure.
